# Requirements

## Purpose

`make dev3` のスタート直後、前方2車の外側だけでなく車間も追い越し候補として扱い、最短で通過できる連続回廊を選択する。

## Functional requirements

- スタートグリッド猶予中は `壁-車 / 車-車 / 車-壁` の3種類の自由回廊を同じ基準で評価する。
- 車-車候補はスタート専用の攻めた半径を使う。壁-車候補はV2Xに姿勢がないため、
  ego/target矩形の最大横半幅と壁余白を適用し、残余幅が閉じた候補を棄却する。
- 必要幅を満たす候補のうち、現在位置からの横移動が小さい回廊を優先する。
- P1は中央trajectory上で加速を続け、P2/P3の発進運動を短時間観測してから、
  イン／車間／外の候補を確定する。観測中にFollowや停止へ落とさない。
- 壁側のイン候補は、最初のヘアピンで固定オフセット曲率が操舵限界内にある場合だけ採用する。
- イン候補を採用した後も、明示追い越し線は各予測点のwall boundだけでなく、
  occupancy mapへ配置したego矩形から0.8 m以上離す。
- 前車のrear-clear確定後はcommitted Pass継続よりReturnを優先し、固定イン目標をヘアピンへ持ち越さない。
- 車間回廊は両側車両IDと回廊中央をロックし、同じ2車の間を継続して狙う。
- 車間回廊が設定距離以上連続して存在するときだけ進入する。
- 回廊消失、V2X位置ジャンプ、明示禁止WP、緊急制動では既存Recovery/SafetyBrakeへ移る。
- 回廊消失後は、永続回廊を検証しない通常のside-clearance fallbackへ再進入しない。
- 片側車両だけを抜いた段階では復帰せず、両側車両の後方クリアを確認してからReturnする。

## Scope and constraints

- 対象は `multi_purpose_mpc_ros` のシミュレーション多車両走行。
- ROS 2 topic、service、message、Domain、評価JSONの契約は変更しない。
- 通常周回の追い越しと停止車両回避の既存動作は維持する。
- 2025由来AWSIM上の暫定レース戦略であり、2026公式仕様ではない。

## Definition of Done

- スタート回廊候補から車間を識別できる。
- 車間の両境界IDをOvertakeLineが保持し、実行中のgap plannerが同じ組を再検証する。
- 代表的な選択・ロック・解放条件に単体テストがある。
- 動的観測の時間上限、候補安定時間、操舵曲率判定に単体テストがある。
- `output/20260722-231926`で誤採用した外側候補を幾何単体テストで棄却できる。
- `output/20260723-062353`で`lb/ub`上は0.8 m余裕があるのに実壁へ接触した目標を、
  occupancy mapの車体判定でreference path側へ戻せる。
- `make autoware-build` と対象テストが成功する。
- `make dev3` のログで選択回廊種別と境界IDを確認できる。

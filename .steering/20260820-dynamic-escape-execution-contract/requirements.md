# Requirements

## 背景

`20260820-113325` と `20260820-113804` では、直前に追加した実行契約ログにより、
solver fallback の停止理由と Pass 失敗理由を追跡できた。

- 動的横回避は reachable bridge の検証後に採用されるが、車体形状を含む静的壁掃引は
  採用契約に含まれていない。
- 動的横回避中の solver 継続判定が、回避経路ではなくレーシングラインに対する
  `e_y` を使うため、正常な横変位を `tracking-envelope-unsafe` と誤分類する。
- Pass の同側再計画拒否理由が文字列だけで、要求横移動と許容上限をログから区別できない。

## 要件

1. 動的横回避候補を採用する前に、現在の実姿勢から候補経路までの車体掃引が静的壁と
   非接触であることを確認する。
2. 採用前検証に失敗した候補は authority を取得せず、反対側候補の評価対象にする。
3. solver の短期継続は、採用前検証済みの動的回避経路をレーシングライン横偏差だけで
   拒否しない。ただし壁、姿勢、緊急停止、連続失敗回数は従来どおり hard gate とする。
4. 候補ログに静的壁preflightの成否・理由・確認pose数を含める。
5. Pass同側再計画の横移動上限拒否には current/desired/adjustment/limit を含める。
6. ROS topic、service、message、launch、result JSON の契約は変更しない。

## 対象外

- gap、壁余裕、加減速度等のパラメータ変更
- Mission/FSMの全面変更
- solver、車両モデル、2026評価インターフェースの変更
- 実走効果確認

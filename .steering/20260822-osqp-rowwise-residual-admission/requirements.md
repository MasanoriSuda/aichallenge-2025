# OSQP rowwise residual admission investigation

## Purpose

Test whether every consumer of the shared OSQP wrapper can safely require the locally computed
per-row residual tolerance.  This was a hypothesis generated by the Track/Cruise shadow boundary,
not an approved production contract.

## Evidence

`output/20260822-232351` exposed three Track/Cruise five-state results whose stage-zero
virtual-progress lower bound exceeded its own row tolerance:

| decision | value / violation | row tolerance |
|---:|---:|---:|
| 4639 | 0.00330833 | 0.00100331 |
| 7799 | 0.00136516 | 0.00100137 |
| 8002 | 0.00174945 | 0.00100175 |

`PersistentOsqpSolver` also serves the production legacy MPC.  Its local per-row report is useful
diagnostic evidence, but it is not identical to OSQP's internally scaled termination test.  A
change at this shared boundary must therefore prove that both the canonical shadow producer and
the existing production controller remain executable.

## Requirements

1. Add the smallest failure-first predicate needed to test the rowwise-admission hypothesis.
2. Preserve OSQP settings, controller parameters and runtime authority.
3. Run the complete package tests and then a clean one-car start before accepting the change.
4. Reject the approach if the common solver boundary invalidates an otherwise established legacy
   start or creates a reset/failure cascade.
5. Record the earliest dynamic counterexample and remove the rejected implementation rather than
   compensating with another fallback, multiplier or exception.

## Definition of done

- The hypothesis is accepted only if tests pass and the production one-car start has no regression.
- If rejected, source/test changes are removed, the dynamic counterexample is documented, and the
  three canonical semantic rejects remain typed fresh-plan unavailability rather than being
  normalized or promoted.

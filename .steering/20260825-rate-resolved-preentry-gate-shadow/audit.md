# Audit

## Finding

The five-state branch solve has one remaining legitimate responsibility: it
proves a prospective ShiftOut/Pass before the live supervisor owns that intent.
The six-state production pipeline cannot simply be called through its normal
builder because that builder derives intent from current live authority. At
pre-entry time this is normally Follow, so its identity would not prove the
Mission about to be committed.

## Data-flow boundary

The existing branch already creates one immutable `MpcProblem`, candidate
path, wall contract, target prediction and prospective intent. The correct
shadow insertion point is immediately after common semantic problem assembly,
inside the existing latest-only tactical worker. This avoids a second world
snapshot and keeps the 40 Hz callback free of branch solves.

## Risk controls

- left/right use distinct six-state solver contexts;
- shadow result has no publisher or production retained store;
- six-state failure cannot reject the current five-state Gate A during this
  evidence Slice;
- target exclusion is checked explicitly rather than inferred from a wall
  certificate;
- no configuration switch is introduced because the shadow is a temporary
  migration stage with a named deletion/promotion gate.

## Dynamic finding

`output/20260825-184710` proves that the prospective context is viable: four
left ShiftOut observations passed the six-state solver, exact swept wall proof
and target-tube proof. Other observations failed independently at the solver
or target proof, so the new trace exposes the real proof boundary rather than
masking it with a generic candidate rejection.

This is not enough to promote authority. Pass and Return were not covered, and
the sample set is too small to prove that six-state availability is at least
as strong as the current Gate A. The five-state Gate A therefore remains the
production selector in this Slice.

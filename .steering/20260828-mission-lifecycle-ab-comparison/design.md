# Mission lifecycle A/B comparison design

## Causal question

The existing resolver gives a complete selected Mission precedence over a
fresh receding prefix.  Therefore ordinary logs cannot answer whether a
failure was produced by the retained Mission or by the common SQP: only one of
the two candidates reaches the solver.

The comparison evaluates both candidates from one owned tactical snapshot.
It is an observation-only fork after world capture and before candidate
resolution:

```text
immutable tactical world
        |-- A: persistent complete Mission -- seven-state SQP -- proof
        `-- B: fresh receding candidate ----- seven-state SQP -- proof
```

## Candidate construction

### A

- `selected_mission` contains the active frozen Mission.
- `mpcc_receding_mission` is empty.
- Resolution must report `CompleteSelectedMission`.

### B

- `selected_mission` is empty.
- `mpcc_receding_mission` contains the fresh candidate generated by the current
  tactical snapshot.
- Resolution must report `RecedingPrefix`.

The comparison is rejected before solving when target, side, phase, provenance
or candidate completeness is not comparable.

## Execution isolation

- Each arm receives an independently owned controller snapshot.
- Both call the existing `evaluate_isolated_extended_mpcc_branch` path.
- The normal left/right production selection is executed unchanged.
- Comparison results are diagnostics only; they cannot populate Mission hints,
  Gate-A proposals, certified-plan mailboxes or control commands.
- Dynamic comparison work is bounded and runs only in the existing async
  tactical worker so it cannot block the 40 Hz control callback.  Its runtime
  is logged because CPU contention remains an experimental confounder.

## Evidence

Every attempted comparison logs one structured `MPCC_AB` record containing:

- decision/world identity;
- phase, source Mission generation, target and side;
- A/B candidate source;
- attempted/solver/wall/target/complete outcome;
- objective, terminal progress/velocity, minimum bound reserve;
- solve and physical-proof time;
- failure detail and causal classification.

The comparison is causal only within one record.  Aggregating unrelated A and
B records from different decision epochs is prohibited.

## Rollback boundary

The comparison instrumentation is independent of production authority.  It can
be removed without changing the ordinary branch resolver, Gate-A admission or
published control path.

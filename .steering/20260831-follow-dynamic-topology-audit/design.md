# Design

## Causal hypotheses

1. **H1 — topology ownership defect.**  Follow leaves longitudinal topology as
   `Automatic`.  The obstacle refinement derives a behind-to-side physical
   diagonal from an obstacle-free wall witness even though Follow owns no pass
   side.  Explicit `StayBehind` is feasible and removes the false authority
   loss.
2. **H2 — affine/nonlinear model mismatch.**  `Automatic` and `StayBehind` both
   fail because the affine state trajectory used by the QP differs materially
   from the nonlinear trajectory generated by the same controls.  The physical
   oracle succeeds only because it re-integrates the controls.
3. **H3 — physical infeasibility.**  Both topology variants and the nonlinear
   controls fail the exact current-world proof.  Existing evidence already
   contradicts this hypothesis, so it remains a falsification check only.
4. **H4 — target prediction provenance defect.**  The convex obstacle tube and
   immutable `ReplayWorld` describe the same target at incompatible velocities
   or stage times.  Both convex topologies can then reject a maneuver which the
   exact timed nonlinear proof accepts.

## Observation-only change

Add one architecture comparison arm for normal `Follow` snapshots:

- clone the sealed snapshot;
- set only dynamic-obstacle longitudinal topology to `StayBehind`;
- recompute the deterministic candidate fingerprint;
- solve and pass the result through the unchanged exact trajectory, wall,
  dynamic-obstacle, and terminal-successor proof chain;
- expose the result only through `mpcc_architecture_compare`.

No store, mailbox, command adapter, publisher, or runtime call site is added.

## Decision rule

- Automatic fails and StayBehind certifies: H1 supported; production fix may
  bind Follow semantics explicitly.
- Both fail, but nonlinear re-integration of the same controls certifies: H2
  supported; repair linearization/bootstrap ownership before changing intent
  semantics.
- Both certify: investigate scheduling/lifecycle rather than formulation.
- Physical proof rejects all candidates: classification remains `Unknown`
  until a bounded infeasibility certificate exists.

## Frozen result

`Automatic` and audit-only `StayBehind` both reach the solver but reject.  The
earliest dominant row changes from the automatic coupled obstacle row to the
stage-4 effective-progress `StayBehind` row, so topology ownership is not the
root cause.  H1 is falsified and no production topology change is authorised.

The immutable inputs expose a stronger upstream inconsistency:

- every semantic MPCC stage is `0.25 s`;
- the recorded target tube advances about `0.097353 m` per stage, equivalent
  to about `0.389 m/s`;
- the same snapshot's `ReplayWorld` target velocity projects to about
  `3.9 m/s` along the recorded course frame;
- exact timed nonlinear replay of the recorded controls still passes wall,
  dynamic-obstacle and terminal proof.

This supports H4, but the present Slice deliberately stops short of replacing
the production prediction producer.  The next MPCC investigation, if resumed,
must rebuild the target tube from the immutable world at semantic stage times
and compare it on the same fingerprinted snapshot before changing authority.

# Design

## Root cause being corrected

The previous `normal_anchor_recurrent_v1` corpus inherited scans from
`dagger_aggregate_v2`.  Those states were generated by `lidar_gap_teacher` or
`lidar_gap_teacher_dagger`, yet were assigned a zero correction relative to the
frozen candidate3 policy.  Replaying the current successor teacher showed that
roughly 11--14% of these alleged normal states require a material correction.
The resulting generalization gate mixed policy disagreement with false
activation and created an artificial trade-off.

## Data flow

```text
frozen candidate3 production run
  -> competition and motion admission
  -> exact runtime/checkpoint proof
  -> finalized LiDAR + odometry bag
  -> timestamp synchronization
  -> immutable train or validation sequence
  -> zero residual anchor
```

The builder consumes successful run artifacts directly.  It does not pass
through a teacher-labelled dataset and does not copy recorded steering as a
target.

## Split integrity

The CLI receives explicit `SPLIT:RUN_DIR` entries.  Canonical run paths and
source-bag paths must be unique.  Sequence identity hashes the run identity,
domain, checkpoint SHA, scan/speed topics and synchronization tolerance.

## Candidate policy

After the corrected dataset is built, rerun the existing separability and
sample-mode spatial adapter experiments without changing production.  Promotion
still requires material-state improvement, direction agreement, production
normal-anchor MAE and independent peer-run gates.

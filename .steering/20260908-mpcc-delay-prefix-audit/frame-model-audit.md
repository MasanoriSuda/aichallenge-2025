# Physical coordinate consistency audit

2026-09-08. This establishes a model defect and a bounded repair design;
the production dynamics remain unchanged. It does not establish that fixing
this defect alone resolves decision 7405 or provides race acceptance.

## Broken invariant and producer

Virtual progress selects the reference frame. With the physical initial
pose, speed, acceleration and steering held fixed, changing this bookkeeping
input must not change the vehicle's Cartesian motion.

Production `mpcc_rate_resolved.cpp::evaluate_temporal_frenet_transition`
uses `ey_dot = v*sin(epsi)` and
`lag_dot = v*cos(epsi)/(1-kappa*ey) - nu`. But world reconstruction in
`mpcc_execution_contract.cpp::reconstruct_planar_pose_from_frenet` uses
`p = r(theta) + lag*t(theta) + ey*n(theta)`. These definitions are inconsistent
when the reference frame rotates or the lateral offset is nonzero.
Both SQP numerical linearization and the alleged exact physical adapter
consume the same inconsistent transition; their agreement is not independent
physical verification. No steering gain, delay or safety margin is changed.

The offline native counterexample compiles the real production transition.
An exact arc-length circle has kappa 0.2/m, initial lag -0.3 m, zero speed,
zero steering and nu 4 m/s for 0.1 s. The physical vehicle must stay at
(-0.3, 0); the native result reconstructs (-0.298187725, -0.039948817):
39.9899 mm of fictitious displacement. Straight-reference negative controls
pass. Positive-speed straight physical motion also fails: v=8, nu=8,
ey=0.2, lag=-0.3 produces 45.5975 mm error in 0.1 s on the same circle.
Across both curvature signs, two physical speeds and four virtual speeds,
14 of 24 cases fail the 0.5 mm invariant. Exit 1 is the expected recorded
pre-repair failure; this is not a passing package regression.

Evidence: `output/20260908-frame-invariance-audit/`, generated by
[check_frame_invariance.cpp](check_frame_invariance.cpp) with production
`src/mpcc_rate_resolved.cpp`. The analytical Cartesian oracle needs no solver,
alternate motion integrator, recorded map or vehicle sensor assumptions.

## Why a two-line equation patch is insufficient

For an arc-length frame the correct coordinate equations are:

```
ey_dot   = v*sin(epsi) - kappa*lag*nu
lag_dot  = v*cos(epsi) - (1-kappa*ey)*nu
epsi_dot = yaw_rate - kappa*nu
theta_dot = nu
```

However `sample_course_frame` linearly interpolates XY and heading separately.
Within the recorded first segment, heading derivative is -0.149090895/m while
the stored stage curvature is -0.166609279/m. The XY chord tangent also differs
from the interpolated heading except at the segment origin. For that actual
frame, define `at=t dot r'`, `an=n dot r'`, `h'=d heading/d theta`; then:

```
ey_dot   = v*sin(epsi) - (an + h'*lag)*nu
lag_dot  = v*cos(epsi) - (at - h'*ey)*nu
epsi_dot = yaw_rate - h'*nu
```

Comparison D integrates these derivatives, including the changing frame, and
agrees with independent Cartesian motion. Comparison B leaves centimetre-scale
error. Therefore adding only the missing rotating-frame terms is insufficient.
This conclusion uses sealed actual geometry, not a request to tune curvature.

## Repair design and acceptance boundary

1. Keep the current failing native and captured-source comparisons. Extend
   regression coverage to frame knots, negative/positive curvature, nonzero
   lag/lateral offset, steering response, and changes of nu with fixed controls.
2. Compare two complete seven-state formulations on the same sealed worlds:
   coordinate-consistent Frenet using immutable reference value/derivative
   sampling, and Cartesian `(x,y,yaw,v,theta,delta,rho)` with progress-dependent
   contour/lag costs. The latter keeps virtual progress out of physical motion;
   the former preserves the current state ordering but needs frame support in
   every transition/linearization/execution path. Do not promote offline
   coordinate comparison D as a solved, certified controller.
3. Include original solver source, SQP Jacobians, artifact/control-stage
   serialization, physical adapter, retained/Stop rollouts, wall/peer proof
   and warm-start/model identity. A new model/schema fingerprint must reject
   old artifacts and incompatible warm starts. One physical motion producer
   must serve normal and Stop paths, with independent Cartesian regression.
4. Remove the obsolete closest-footpoint denominator law from the changed
   virtual-frame transition. Audit every remaining use separately: a physical
   course projection or Stop progress estimate can have a different meaning.
   Do not remove validity guards or introduce a fallback to make tests pass.
5. Run fixed-input feasibility/architecture comparisons and verify all hard
   wall/peer/terminal contracts before one bounded dynamic diagnostic. Then
   repeat the fixed integration campaign; retain failures and all old trials.

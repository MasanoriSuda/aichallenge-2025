## Identity and integration obligations

- A numerical initializer is not a new control formulation or a soft-cost
  change. Record it explicitly with the immutable solver source and include it
  in replay serialization/fingerprinting. Old default source replay stays valid.
- Reserve distinct solution/source identities for the two candidates BEFORE
  dispatching the worker. Keep decision/context/world shared; do not relabel a
  returned artifact or mutate a captured source in place.
- Give the initializers independent persistent numerical/warm-state owners.
  Unknown initializer values fail closed; every candidate still solves the
  current full QP and all current source physical proofs.
- Latest-only mailboxes and the certified Store must understand one source
  population without permitting older unrelated work to overwrite it. The
  physical mailbox currently requires the exact latest submitted identity;
  reserving two IDs naively would wrongly supersede a valid member. Preserve
  explicit group identity and test both members/older groups/late completions.
- The existing target-dependent avoidance/overtake populations keep their
  current ownership unless separately covered. The immediate failing world
  is target-free Cruise; Follow is a regression comparison, not evidence to
  rewrite its Mission lifecycle.
- Measure total candidate work and actual source age/availability. A second
  bounded solve may add latency; no budget, reservation or timeout is enlarged
  to hide it. R519 is an offline comparison only.

Before production, require old failure/new complete proof, deterministic bounded
selection and full serialization/identity negatives; existing successful sources
and unsafe current snapshots; source review, full build/package tests and a new
committed standard run. Retire the single-initializer-only source path in the same
